# 制作组隔离检查与结论边界

检查范围：本批 Control、Sable、DREDGE 的 12 个制作 agent，共 601 条可见工具调用记录。仅查看本任务的工具输入、相关输出和文件路径；不归档私人会话日志。此前 Hi-Fi Rush 四组不在这次访问检查范围内。

**未发现直接读取其他组美术图片、场景、材质或 shader 的记录；但本轮不能称为严格隔离。** 各组使用新上下文，收到禁止读其他成果的指令，却共享宿主文件系统、Git 仓库和临时目录。可见记录没有违规，不等于访问在权限上不可能发生。

## 发现了什么

| 接触类型 | 具体记录 | 对结论的影响 |
| --- | --- | --- |
| 其他组提交标题 | Control C 无路径限制的 `git log -1` 看到了 Control D 的档案交接/座椅/门口照明标题；Control D 看到了 Sable C 的吊装/货运/入口标题。两者均发生在自己最终图已查看之后、准备提交时。 | 暴露了美术方案的摘要。时序不支持用这些标题解释已完成终图，但隔离设计仍有缺口。 |
| 共享 Git 元数据 | 若干组查看整个暂存区的文件名、统计或 diff 格式检查；Sable D 也读到了公共捕获修复的提交标题。 | 接触文件名、进度和技术变更；没有找到跨组艺术内容 diff。 |
| 其他组临时工具 | DREDGE C 读取了 Sable B 的临时 Python 启动脚本；其内容只有解释器和依赖路径。另有临时目录文件名探查。 | 未含美术内容，但共享临时工具破坏了输入边界。 |
| 制作组间协调 | Control B/Sable D、Control D/DREDGE D 有共享 Git 提交协调调用。 | 本地调用记录的消息参数部分不可读，不能声称完整审查了全部消息正文。父 agent 可见的协调摘要不提供美术反馈。 |

可见图片调用指向固定参考、自己的起点/首轮/终图、自己的纹理或派生预览；未发现其他制作组的艺术输入路径。唯一实际内容式 Git diff 对象是本组 project.godot；未发现通过 `git show` 读取其他组文件。以上是本次有限记录检查的发现，不是操作系统级访问证明。

## 为什么仍会趋同

四组从同一个**完成过多轮的局部**开始，使用相同参考、素材池、镜头和轮数；输入中的既有构图与说明已经限定了很大一部分设计空间。这本来就会倾向于相似的补充和修整，不能只凭画面接近推断互相抄用了成果。

因此本批归类为：**逻辑隔离不完整的续作比较**。可以比较这批图中的细节、统一性与灯光，不能据此评价独立找素材、从白盒重建的能力，也不能证明 effort 越高越好或某个档位普遍最划算。

## 下一批的修改
