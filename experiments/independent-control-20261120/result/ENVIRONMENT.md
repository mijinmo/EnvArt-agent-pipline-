# Control：室内档案交接局部

任务：从提供的原始白盒完成一个可编辑、可近看、可试玩的 Control 方向室内局部。验证参考发现、真实素材筛选/适配和整合能力；这是单组管线验证，不做模型或 effort 排名。

## 范围与空间意图

- 主场景 `whitebox.tscn`，几何/碰撞来源为 `demo/controller_lab.tscn`。单位为米。
- 本轮完成门洞及右侧墙角形成的档案交接工作区：主要可见区域 x=-2..10、z=-10..1；相邻部分只补视觉上必需的连续围护与地面，不扩展全场道具制作。
- 空间明确为室内：原白盒缺顶属于未完成围护，不代表室外。可补建净高约 4.5 m 的顶棚、上部墙体、支撑、合理天窗/玻璃或实际灯具；围护不得切断原路线。主光源及室内建筑语言由实际参考研究确定。
- 保留所有原始 StaticBody3D、CollisionShape3D 的尺寸、位置和旋转；可以隐藏它们的占位 Mesh 并覆以实际素材。门洞 x=-0.6..0.6、净高 2.3 m、z≈-4 的通行范围不得侵占。坡道、台阶、跳台保持原形状，位于局部外的部分可以继续白盒状态并明确标示范围。
- 原始玩家与相机是只读基础设施。保留可试玩入口，不添加控制器、交互面板或功能回归套件。
- `views.json` 固定门洞、墙边组与近看三个机位；位置、朝向、FOV、1280×800 在白盒/首轮/最终中保持一致。它们是本轮固定机位，不要求和此前的成品机位比较。

## 制作与证据

1. 阅读 `skills/godot-envart/SKILL.md` 及相应 references。
2. 独立搜索并实际查看 Control 室内环境参考，记录精确来源、能证明的内容和局限；不要把战斗特效或概念画当作唯一环境证据。参考图只在 `.work/references/` 私有缓存，未确认再分发权利时只提交 URL/哈希/观察记录。
3. 独立检索、下载、检查建筑构件/表面与叙事道具素材。主要建筑和道具须体现真实素材；核对实际免费文件、可商用与再分发范围并保留许可。必要 Blender 改造与 shader 允许；自制基本形状只能补缺，不能代替素材筛选。
4. 至少做一组可对照的素材小样：主墙面完整重复尺度 + 相邻代表道具，在 Godot 中实际出图再选择。
5. 建立 `first.tscn` 后重开并拍三图，实际看图后自主修订一次，保存 `final.tscn` 与第二组三图。冻结首轮及其依赖，修改共享资源时为新版本复制，不能覆盖旧证据。
6. 交付场景、资产及许可清单、参考来源、两轮实机图、简短可见问题评价和打开说明。未达到的部分如实列出，不用技术通过替代美术验收。
7. 每个可独立验证阶段都在本组自己的 Git 仓库提交；保留 `.uid` 和源侧 `.import`，排除 `.godot/`、临时下载包和日志。

必要命令（本机已验证 Godot 4.7.2 / Blender 5.2.1）：

```sh
godot --headless --path . --editor --import --quit
godot --path . --rendering-driver metal --script res://capture.gd -- first.tscn captures/first
```

F5 主入口最终指向 `final.tscn`；5/6/7 固定机位，1/2 玩家，3 自由相机，WASD/鼠标，Space 跳跃，Esc 释放鼠标。仅导入、加载、真实渲染及受变更影响的通行/视线检查；不要全套功能测试。
