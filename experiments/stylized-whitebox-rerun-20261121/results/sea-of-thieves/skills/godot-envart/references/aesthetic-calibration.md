# User aesthetic calibration and revision handoff

Use for a new visual direction, consequential ambiguity about taste, a substantial change of direction, or an authorized fresh-agent revision. Reuse existing decisions for a narrow edit. This is an art-production procedure, not an automated approval system or a reason to launch more agents.

## Carry the target between sessions

The coordinator reads the project's aesthetic record and applicable user feedback before preparing a task. Give every producer/editor/reviewer the relevant requirements, spatial constraints and original reference evidence. Separate explicit user decisions, visible observations, proposed implementation and unresolved choices. A new context must receive this knowledge in the brief rather than rediscover it from unrelated result archives.

Keep project-specific taste in the project's own record, with scope and evidence. Generalizing a rejected concrete texture into a ban on all concrete joints, or a rejected realistic experiment into a ban on its asset vendor, loses the user's meaning. A statement that one pass improved is not approval of every element or permission to expand the level.

## Calibrate after a representative direction draft

Prepare one saved-engine local draft with representative architecture/ground, a major prop group, intended material treatment and basic motivated lighting. Use the established overall, close and transition views as applicable. Fix missing materials, unreadable captures and accidental occlusion before presenting a taste decision. The user should be able to judge form, material and light together without waiting for all decoration to be finished.

Usually present one main proposal and the relevant reference. Add one bounded alternate only when it resolves a real ambiguity; reuse the scene and identify what changed. Do not make a full matrix of finished environments just to ask for a preference.

The coordinator summarizes known requirements and remaining uncertainty, then asks only what is needed to choose the next art action. Useful feedback identifies what to retain, the one or two largest visual failures, and whether to refine the direction or revisit form/assets/rendering. Do not ask the user to repeat settled requirements or diagnose import failures. Do not bury the pictures under implementation explanations or self-scores.

Translate the response into observable targets in the existing brief/review record. Preserve the user's wording separately from the coordinator's interpretation. Tie each target to image regions and viewing distances, identify elements to retain, and state what new image would support improvement. For example, a lack of comic rendering may lead to a hypothesis about broad light bands, mechanical proportions and value grouping; adding an outline is only one possible implementation.

User calibration is needed at meaningful direction decisions, not every edit. Once the direction is sufficiently established, continue within the agreed scope and allowance. If a consequential preference remains unanswered, keep it pending, preserve the last acceptable pass and advance only independent work; do not turn silence into acceptance or spend the remaining budget guessing through a full scene. Existing authorization and explicit unattended-work preferences still apply.

## Make the responsibilities explicit

| Role | Responsibility | Boundary |
| --- | --- | --- |
| Coordinator / main agent | Assemble requirements; present calibration; translate feedback; prepare handoff; review same-view results and select the better saved pass | The coordinator's recommendation is separate from user art acceptance. |
| A / producer | Find and adapt assets, build the direction draft, save editable resources and real captures; may continue normal refinement | Completed tasks or effort spent do not establish quality. |
| B / fresh editor, when authorized | First diagnose the assigned images independently; then inspect the project and perform the agreed revision | B edits the designated candidate; B does not provide final independent acceptance of its own edit. |
| User | Set aesthetic priorities, resolve meaningful taste choices and accept the delivered art | Technical diagnosis and routine fixes stay with the agents. |

The minimal additional handoff is **A produces → B edits → coordinator reviews**. The coordinator may calibrate with the user between the draft and editing. A self-revision remains a valid option when no fresh editor is needed or authorized; do not spawn B solely because this document exists.

Give B the original references, scoped user requirements, frozen initial images and protected whitebox/camera constraints first. B records at most three dominant visual issues before reading A's self-evaluation or detailed solution narrative. Then provide the saved scene/resources, asset licenses, brief revision and necessary technical notes. There is no need to transfer the complete conversation or every intermediate tool log.

Prioritize dominant form/spatial hierarchy, material/style compatibility and lighting before isolated labels and small props. A functional prop story supports composition; it does not compensate for the wrong main asset. B may return to asset selection for a bounded replacement when the diagnosis requires it.

Default to one authorized handoff and one focused art revision within the assigned allowance. Preserve A's scene **and its mutable dependencies**, write new captures without overwriting the draft, and commit the reviewable stage under project conventions. Repeated editor chains or additional effort tiers need a task reason; a handoff alone does not authorize a batch experiment.

## Review improvement and stop appropriately

The coordinator inspects before/after images at the same camera and comparable capture conditions, checks the stated targets across the affected views, and notes regressions. Verify only import/load/render and directly affected whitebox constraints. A review report, more props or more shader features is not evidence of improvement.

If the revision fails, retain the stronger pass and record the unresolved cause. Return to the responsible upstream decision; ask for user calibration again only if a genuine preference or scope conflict has emerged. Direction agreement, agent visual verification and final user acceptance remain separate states.

## Keep records and comparisons small

Use the existing task brief/review; no new database or required form is needed. At a handoff it should identify:

- Current scene/pass and frozen evidence; inherited skill/brief revision.
- Applicable user decisions and their scope; outstanding calibration questions and provisional interpretations.
- What must remain, the few requested changes and the views used to assess them.
- A/B/coordinator ownership, permitted predecessor input and the revision allowance.
- Resulting evidence, selected pass, regressions and user acceptance status.

For an explicitly requested independent trial, follow [independent-trials.md](independent-trials.md). Share the same applicable user constraints across candidates while isolating candidate solutions. A declared A-to-B handoff is allowed inheritance and must be labeled as assisted revision; B is not a new from-whitebox sample. Comparing A self-revision with B revision requires the same frozen draft, feedback, reference and work allowance, with no reading of the other branch.

Fresh-agent revision is a hypothesis about better art, not a proven saving. If the user cares about actual Codex allowance, keep that distinct from raw/cached token counters, include coordination/review in the recorded scope when available, and do not claim a quota conversion that was not measured.
