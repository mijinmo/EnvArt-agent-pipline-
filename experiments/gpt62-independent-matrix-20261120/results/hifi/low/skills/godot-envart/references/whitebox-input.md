# Whitebox handoff

Keep this brief compact; record decisions, not a new metadata framework. Resolve spatial intent before architecture selection and lighting. Mixed scenes should identify indoor/outdoor regions and their transition.

```text
Whitebox scene and work area:
Spatial type: indoor / outdoor / semi-open (by region if mixed)
Enclosure: intended ceiling height or open sky; outer walls; windows/skylights/door openings
Omitted geometry: unfinished shell vs deliberately open space
Permitted additions: ceilings, outer walls, support structures and background; protected boundaries
Protected play space: routes, clearances, ramps, steps, jump surfaces and required sightlines
Visual references: exact images; dominant forms, surface continuity/joints, palette and detail scale
Lighting intent: time/weather if relevant; daylight openings; practical sources and focal area
Review slice: main view, nearby inspection views, expected visible completion
```

Use information already supplied by the user or clearly established by the references; do not re-ask settled choices. If spatial type or enclosure is unresolved, flag that missing decision and ask before constructing the shell or committing to a light rig. Asset license checks and reference study can continue independently. A source whitebox missing its roof is ambiguous, not permission to make an interior an exterior.

Example of a surface requirement: “The selected interior reference reads as large continuous concrete masses. No conspicuous texture-tile grid or repeated stain motif at player distance; construction joints only where supported by the reference.” This is a brief-specific choice, not a rule that all concrete or every scene from one game must be joint-free.
