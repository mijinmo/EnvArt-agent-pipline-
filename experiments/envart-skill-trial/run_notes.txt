EMBERWATCH / independent environment-art skill trial / 2026-11-13

Opened and viewed all six supplied images. Chosen target: stylized ashen fortress, with slate stone, subdued timber, rust-red heraldry and warm practical pools. Small activity: a watch-post ration and pay station (food, plate stack, bottles, coin stacks, seats, barrel stock), not a prop catalog. Complete slice has a real arched opening, raised watch platform and timber stair, modular paving, weathered margins, ruin wall/towers and terrain support.

Project is independent and empty-origin. No original project scenes, controllers, assembly scripts, docs or tests were read/copied. Built from the skill plus its Godot delivery note and the six references. No new plugin or asset-archive code was executed.

Workflow: verified creator CC0 terms and retained original license; inspected source GLB bounds/pivots; imported selected family; initially captured in Godot 4.7.2 OpenGL/Compatibility; inspected actual images across four art passes, then matched the reference Metal Forward+ renderer for final contact-shading calibration. First image exposed severe over-brightness, a misleading wall_arched asset (solid recess rather than opening), and absent support ground. Subsequent passes corrected light/material response, substituted wall_doorway_sides, added continuous terrain, fixed terrain triangle winding, reduced/grounded perimeter rubble and reframed overview. Earlier captures retained in captures/iteration-01 through iteration-03.

The final TSCN contains editable native nodes and editable GLB instances; original UV texture remains on every asset, with local material overrides. build_scene.gd can reproduce the scene but is not needed to open it. inspection.gd only switches four static cameras and optionally saves viewport captures. No controllers, collisions, gameplay systems, test suites or benchmark systems were introduced.

Skill observations: its visual-first scope and explicit prohibition on function-test sprawl were useful. The ownership and force_draw notes were directly useful. Asset names do not reliably distinguish an opening from an arch relief: source bounds alone did not catch this. The material/exposure problem should have been caught with a representative in-engine sample before full dressing; here the first composed capture served that purpose. The skill does not prescribe a renderer/exposure baseline; this requires visual calibration. Terrain winding on Compatibility was another visible-only error. No permission ambiguity arose.

Remaining visual limitations: terrain is deliberately simple and distant ruin repetition is visible; dirt/paving transition retains angular modular edges; sparse foreground and simple material textures flatten some surfaces; timber steps are steep and lack a continuous handrail; far backdrop does not reach hero-asset detail. This is a small stylized art study at the provided reference direction, not a production-complete or user-art-approved environment. Successful rendering is not art acceptance.

Opening: import project.godot into Godot 4.7.2 using its configured Forward+ renderer (captured on Metal 4.0 / Apple M5), open courtyard.tscn, press F6 or run F5. Keys 1/2/3/4 select overall / entrance / activity / ground-transition. F8 stops. Editable scene is directly reviewable in the editor. Optional capture: Godot --path PROJECT --log-file /tmp/emberwatch.log -- --capture. Capture output: captures/overall.png, entrance.png, activity.png, transition.png. Real viewport PNGs, 1280x800, no image-generation or postprocessing.

FINAL RENDERER CORRECTION
The original Compatibility selection was an unverified convenience assumption for a lightweight screenshot workflow, not a platform limitation or artistic requirement. Root identified that the references used Metal Forward+ with AO/indirect light. Final project now uses Forward+ directly on this M5 with SSAO radius 1.2 / intensity 1.1 / power 1.5 / detail 0.5, SSIL radius 3.0 / intensity 0.65 / sharpness 0.85, shadowed existing sun and practicals, ambient 0.55 and sun energy 1.25. All four camera transforms, composition and assets remained fixed. The first Forward+ pass was too dark; one lighting adjustment restored material readability while keeping contact shading. Native script UID sidecars were generated through normal editor import. No backend test suite was added and no renderer blocker occurred.

Final Forward+ captures occupy captures/{overall,entrance,activity,transition}.png; former final Compatibility views are preserved in captures/compatibility-final/ and first Forward+ lighting pass in captures/forward-initial/. Final images visibly deepen shelf/brick/stair recesses and contact under bottles, barrel hoops and furniture. The scene remains subdued; ground margins and sparse distant layer remain the same admitted artistic limitations.
