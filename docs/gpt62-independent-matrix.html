比较边界

每组是全新 Git、上下文、制作和缓存目录。每个游戏的六组有相同冻结参考、白盒和 skill，素材由各组独立发现。每组首轮出图并自主修订一次，协调者不提供美术解法。场景、素材许可、首轮与终图一同保存。

CLI shell 和专用 Godot 渲染进程实施组间文件限制。图片工具等访问面的证据与限制单独报告；不把没有发现跨读说成所有工具都已证明绝对隔离。所有制作组关闭进一步委派，ultra 也是单制作 agent 条件；它不代表开启自动委派的完整 ultra 工作方式。

如何使用结果

先选最接近目标方向且缺陷可修的局部，再结合素材适配和修订记录提取可复用步骤。若质量接近，可用实际用量辅助取舍。一次结果不足以证明某档普遍最优；代理偏好也不等于用户美术验收。

每个工程用 Godot 4.7.2 导入，F5 打开 final.tscn；5/6/7 固定机位，1/2 玩家，3 自由观察。原控制器和白盒通行约束保留，范围外仍可能是测试几何。其他平台渲染未验证。
