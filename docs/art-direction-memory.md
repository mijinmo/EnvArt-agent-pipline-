# 项目审美要求与验收依据

更新：2026-11-20。供新主 agent 接续本项目时读取；依据本项目用户对话与已有成果整理。这里保存跨轮次的用户要求及其适用范围，不替代当前场景的参考、brief 和实际看图。

**主 agent 先读本文件，再向制作/修改/评审 agent 提供与任务有关的要求。** 新上下文不能只获得流程步骤而丢失审美目标。独立试跑的制作组只收到提炼后的要求与允许的参考，不直接浏览本文件链接的历史成品。

## 已明确的共同要求

| 用户要求及对话依据 | 对制作与验收的含义 | 适用边界 |
| --- | --- | --- |
| 环境美术是主要产出；“不要做冗余的功能型验证” | 优先把可编辑局部和真实实机画面做对；检查导入、渲染及受影响的白盒约束。 | 不另造控制器、交互面板或通用验证框架。 |
| “不是说先找素材吗”；“几乎没有任何装饰性 props” | 主要可见建筑与道具先筛选、下载、查看真实可交付素材；局部需要可近看的细节与道具搭配。 | 程序化可补缺口、散布和远景；下载数、物件数不证明美术质量。 |
| “植物和写实素材还是有点不搭，货箱堆也太整齐重复了” | 检查相邻资产的造型、细节精度和材质语言；用功能、状态和疏密变化组织道具。 | 并非禁止所有低多边形或所有写实素材。选材应服从当前方向。 |
| 地面灰模曾被明确指出 | 代表性初稿需包括地面、门槛、主要边界和基本照明，不能只完成桌面或一面墙。 | 仍先完成局部，不擅自扩展全场。 |
| 宣发图经常以角色为主，不适合作环境参考 | 选择环境清晰的具体图像，标出其能支持的形体、材质、道具和光照判断。 | 宣发来源不自动淘汰，实机来源也不自动合格；以可见环境证据为准。 |
| “后续白盒 input 需要确定好是室内还是室外场景” | 明确室内/室外/半开放、围护、屋顶、采光开口及允许补建范围；保留通路和关键白盒形状。 | 原白盒缺屋顶不代表室外。 |
| 光影细节需要加入评判 | 早期就建立合理光源、明暗主次、接触和远近层次，连同材质一起看。 | 不把更暗、更亮、更多雾当成自动改善。 |
| 感觉像 retro/千禧年风格，和最初写实预期不符 | 实际结果偏离方向时应承认差距、调整选材/制作，不能改称另一种风格就算完成。 | 用户后续明确选择风格化方向时，按该方向参考工作。 |

这些要求来自连续反馈，不能简化为“多放 props”或“提高 effort”。主要形体、空间层次、材质统一与光影都需要在实图中成立。哪一项优先修，仍由当前画面与用户目标决定。

## 有范围的方向要求

| 范围 | 用户已明确 | 还不能当作用户定论 |
| --- | --- | --- |
| Control 室内局部 | 补顶棚与合理采光；解决墙面明显 tile 痕迹；去掉 tile 后仍需混凝土质感、道具密度和光影层次。 | 不能推导成完全无接缝、纯色墙，或所有 Control 局部必须使用同一套家具。 |
| Hi-Fi Rush 漫画表达 | 一次 outline 不足够，模型和材质也要符合漫画表达；允许按参考制作风格化 shader。 | 具体风机、机械臂、配色或 shader 算法属于方案，不是用户指定答案。 |
| Sable / DREDGE 等独特风格 | 用户要求尝试不同优秀游戏方向，检查找素材、细节填充、风格统一，后来补充光影。 | 尚无用户对某个 effort 档位或某套灯光/道具的普遍认可；按选定参考校准。 |
| Poly Haven 写实替换实验 | 用户明确停止该方向，后续不继续推进。 | 停止的是该实验方向，不是禁止在其他合适任务中使用 Poly Haven 素材。 |

## 2026-11-20 确认采用的流程调整

用户已同意在首个能判断方向的实机局部之后、集中细化之前增加审美校准。复用上面已知要求，只询问有实质影响的剩余分歧；通常提供一个主方案，必要时一个局部对照。每次编辑都重新确认不是本流程要求。

角色为 **A 制作初稿 → B 在授权接手时诊断并修改 → 主 agent 对比实图复核**；主 agent 负责把用户反馈写回任务 brief。常规修订也可由 A 完成。最终美术验收属于用户，不属于 B 的自评。

这一流程的设计已确认，**校准与接手修改带来的实际质量/额度收益尚未验证**。不是继续批量跑六档、扩展全场或恢复本 MacBook Godot 运行的授权。用户关注的是实际 Codex 使用额度，不能拿 raw/cached token 总数直接换算额度。

## 接续时怎样使用和更新

当前场景只在已有 `ENVIRONMENT.md`、brief 或 review 中维护一份实际决策：当前场景/截图版本、所用参考、已知要求、待校准项、需要保留的特点、少数修改目标、负责的 A/B/主 agent、下一步和用户验收状态。不要为这次调整新增一套平行记录系统。

主 agent 转述反馈时区分“用户原话”“实现解释/假设”和“新图验证结果”。比如“漫画感不足”已确认，采用哪种明暗分段或机械比例属于待验证的实现选择。用户未回复的判断保持未决，不替用户写成接受。

只有新增或改变了跨轮次的用户要求，才更新本文件，并注明场景范围、对话依据和相关证据。某张图的问题留在该任务记录中；agent 的偏好不得自动升格为项目规则。
